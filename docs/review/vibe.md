# Adversarial review, ODIA-V3 @ d0109d7

## Findings, most severe first

**1. `-mass_calibration off` is silently ignored when `-rt_mode auto` — medium; bites on real input.**
`DIATraceExtractor.cpp:~289` starts the calibration panel whenever `mode == "auto" || mass_auto`, and `DIATraceExtractor.cpp:~413` applies `eopt.ms2_ppm_offset = cal ? cal->ms2_offset_ppm : getDoubleOption_("mz_offset");` whenever `cal` exists. So `DIATraceExtractorExtractor -rt_mode auto -mass_calibration off -mz_offset 5 -mz_tol 10` still runs calibration, applies the *measured* offsets, and (with the default `-mz_tol 0`) the measured tolerances; the user's `-mz_offset 5` is discarded without a warning. Any run combining "auto RT" with "off mass" gets mass correction the option text explicitly says should not happen ("apply them **instead of** -mz_offset*" is only documented for `auto`).

**2. TSV output buffers a whole unit's text per item; up to 256 items in flight — medium; bites real users of `-out_tsv`.**
`TraceWriter.cpp:~345-360` builds one `e.tsv` string per unit (one text row per point), and committed-but-unwritten items holding `Encoded` are capped only by `SchedulerOptions::max_unwritten = 256` (`Scheduler.h:27`, enforced at `Scheduler.cpp:~318`). Failing state: `-out_tsv -rt_window 0` on a 10k-cycle run: one unit = 256 precursors × ~9 traces × 10k points × ~90 bytes ≈ 2 GB of string; two units in flight and the process is dead. With the default 60 s window it is ~12 MB × in-flight units — several GB. Parquet is unaffected (binary blobs ≈ points × 4 B). OOM, not wrong output.

**3. `-log8_decades` ≤ 0 with `-encoding log8` → NaN → UB cast — low; only with a nonsense option value.**
`TraceWriter.cpp:~328-332`: `x = 1.0 + log10(v/vmax)/decades` divides by `decades` with no validation (`registerDoubleOption_("log8_decades", ...)` has no min). `-log8_decades 0 -encoding log8` gives `x = ±inf/NaN`; `std::clamp` of NaN is NaN and `static_cast<std::uint8_t>(NaN)` is UB — garbage intensity bytes, no error. Should reject ≤ 0 at option parse.

**4. The calibration fallback catches only `std::runtime_error` — low; semi-real.**
`DIATraceExtractor.cpp:~364` (`catch (const std::runtime_error& e)`). `robustFit`'s own guards throw `runtime_error`, but the OpenMS model fits inside `RtMap::fromPoints` (`Calibration.cpp` `robustFit` → `RtMap.cpp:fromPoints` → `trafo_->fitModel`) can throw `OpenMS::Exception::*` (derived from `std::exception`, not `runtime_error`) on degenerate anchor sets (e.g. all anchors at identical RT). Those bypass the "warn and continue with explicit tolerances" path and surface as an OpenMS error via TOPPBase instead of the intended graceful degradation with `-rt_mode linear -mz_tol 10`.

**5. `MzMLFast` accepts MS2 spectra with no isolation window → phantom `[0,0]` lane — low; theoretical for DIA.**
`MzMLFast.cpp:~196-203`: `parseSpectrumHeader` returns true for `ms_level >= 2` with `have_target == false` (no MS:1000827 and no selected ion); `target/lower/upper` stay 0. `Router::windowId_` then creates a window with `lower == upper == 0` that participates in cycle closing. Every DIA file has windows, so this needs a hand-made or DDA mzML; the failure mode is extra cycles/lane, not corruption. Falling back to OpenMS would not change the outcome (OpenMS also yields a 0-width window), so this is consistent-between-parsers, just surprising.

**6. `attribute()` can be spoofed from inside another attribute's value — low; adversarial/theoretical.**
`MzMLFast.cpp:26-45`: a match only needs *whitespace before* the name and `="`/`='` after it. A spectrum tag like `<spectrum ... userParam name='x accession="MS:1000827" value="999"' ...>` placed before the real attributes (attribute order is arbitrary in XML) would be parsed as an isolation target of 999. The `start_ok` whitespace guard blocks the realistic cases (`unitAccession`, `defaultArrayLength`); you need a file deliberately crafted to lie.

**7. `ArrowPool` thread-local `Local` vs. static pool destruction order — low; latent, not reachable today.**
`ArrowPool.cpp:~48-85`: `~Local` dereferences `owner` (the function-local-static pool) and locks its `free_` mutexes. If any thread whose `Local` was created exits *after* the static `RecyclingPool` is destroyed, that is use-after-destruction. Today all `arrowPool()` users are the main thread and joined `std::thread` workers (encode/write); OpenMP worker threads never allocate from it, and glibc runs main-thread TLS dtors before static dtors — so it is dormant. It becomes live the first time any OpenMP-parallel stage allocates through Arrow.

**8. `orderedParallel` deadlocks if called with `ahead == 0` — low; latent API hazard.**
`Pipeline.h:~46`: `cv.wait(lock, [&]{ return i < next + ahead || error; })` — with `ahead == 0`, the worker holding `i == next` waits forever. Current callers are safe (`examinePanel` passes `4 * threads`, `loadChunked` passes `min(2*threads, 32)`), but nothing enforces `ahead >= 1` at the interface.

**9. Peak-pool capacity `bytes/2` is exhaustible by pathological mzML — low; theoretical, clean failure.**
`RunGrid.cpp:~690-698`: capacity = file bytes / 2 peaks (×4 for non-`.mzml`). Uncompressed 32-bit arrays cost ≥ 10.7 file bytes per peak, so real data has ≥ 5× headroom; but a synthetic, highly zlib-compressible mzML (all-zero intensities, linear m/z ramp, < 2 file bytes/peak) exceeds it. `PeakPool::claim` (`RunGrid.cpp:~634`) throws a clear "peak pool exhausted" error — a clean abort, not corruption.

**10. Stage-1 calibration tile memory scales as panel × fragments × cycles per thread — low; real only for very large libraries.**
`Calibration.cpp` `examineWholeRun` (~line 300): tile = members × 6 × cycles floats, per window task, with `threads = min(opt.threads, 32)` concurrent buffers that only grow. A 7 M-precursor library at the default 5 % panel (350k), 64 windows, 10k cycles ⇒ ~1.3 GB per worker × 32 ⇒ ~40 GB resident. Fails as `bad_alloc` → `INTERNAL_ERROR` (not caught by the `runtime_error` fallback), so it degrades to an error, not wrong output. Indexing by `omp_get_thread_num()` and the 32-thread cap are correct.

**11. `ms1_isotopes > 127` wraps the int8 `isotope` column — low; theoretical.**
`TraceWriter.cpp` `iso.Append(static_cast<std::int8_t>(isotope))`: `-ms1_isotopes 200` writes isotope 200 as −56. Nobody extracts 200 isotopes; a `setMinInt_`/`setMaxInt_` bound would close it.

## Verified fine (attacked, no bug found)

- **`Extractor.cpp` `join` (area 1): correct.** The aggregation loop (`Extractor.cpp:~199-202`) scans with a *local* index from `p`, and `p` only ever advances to the first peak ≥ `t.lo` (`seek` provably never overshoots lower_bound; `if (q > p)` guards). So overlapping/duplicate windows *within and across records* — equal `lo`, one window containing another, duplicate fragment m/z — all give exactly the naive per-target `lower_bound` + max/sum. Targets with windows above every peak write 0; spans opening/closing in the same cell are merged then removed correctly; records with zero cycles occupy a `{0,0}` span that is never merged; record spans are monotone (RT-sorted assignments, monotone `lowerCycle`/`upperCycle`), so the `r_in` merge and `remove_if` bookkeeping is sound; MS1-on-scan-axis is the same algorithm on the MS1 lane. **Empty cells are the one case where the join writes nothing — and that is correct only because `TraceArena::alloc` memsets (`BufferPool.cpp:~113`); the pool/heap paths both zero.** This invariant is load-bearing: if `alloc` ever stops zeroing, padded cells (any window skipped in a cycle) would emit recycled garbage.
- **Calibration iterative mass search (area 2): no sign error, no double application.** Offsets are applied once per pass to the *uncorrected* library m/z in `fragmentBounds`, and errors are recorded relative to the uncorrected target (`scoreTile`), so the offset never compounds. `narrowed = min(50, 3×accuracy)` can widen if the measured width grows — that is arguably right, not a bug. The round loop is capped by `max(1, search_rounds)` and breaks on <25 % change in both MS2 and MS1 widths; an empty MS1 model (`m1.n == 0`) freezes its width, which converges. `massModel` handles n=1, all-equal errors (floor `max(k·sigma, 0.1)`), and empty input (`n=0` → keep previous width). `bins = max(1, min(20, n/10))` with the ≥50-anchor gate means every bin has ≥5 anchors, so `modes` is never empty (the `modes.front()` dereference is safe). `kept.size() >= 20` correctly disables the filter. `robustFit` throws a catchable `runtime_error` below 10 usable anchors. Stage-1 `examineWholeRun` and per-precursor `examine` produce identical traces (same skip rules, same tie-breaking, monotone-pointer walk ≡ `lower_bound`).
- **`RunGrid` (area 3): routing is sound.** Cycle closing on window repeat, `padTo_`, the duplicate-cell guard (unreachable by construction, as commented), lane sort, and `finish()` closing the trailing partial cycle all check out. `loadChunked` cuts only at `<spectrum` start positions, so a spectrum is never split; the 16-byte lookahead covers a tag straddling a 1 MiB block; comments/DOCTYPE inside the run, wrong `count`, or `<64` spectra fall back to the streaming parser. `loadMzPeak` writes only claimed ranges; `ms_level` 0/other spectra are decoded but skipped by the router without touching `pool_begin`; worker exceptions are captured and rethrown on the main thread. `buildIndex`'s bucket table is a lower bound on `lower_bound` (never overshoots) and disables itself above 65,535 peaks per cell.
- **`MzMLFast` (area 4): the supported subset is handled and everything else fails *closed*** — numpress, missing bits, missing time unit, wrong `defaultArrayLength`, length-mismatched zlib, mid-stream `=` all return false → per-chunk OpenMS fallback, never silent misparse. Minutes (`UO:0000031`/`MS:1000038`) → ×60; seconds `UO:0000010`; unknown unit → fallback. Attribute order does not matter (whitespace-guarded scan), except the adversarial case in finding 6. `defaultArrayLength="0"` yields an empty cell. 32/64-bit widths checked against the decoded byte count.
- **`Scheduler` / `Pipeline` (area 5): no deadlock found.** In-order issue, `parts_ahead`, `unwritten` cap and the `ahead` window all drain independently (encode/write never depend on new extraction; the next-to-commit unit always runs, on the heap if the block pool is empty — `Scheduler.cpp:~312-316`). Every state transition that can unblock a waiter is followed by `notify_all`; `finished_()` covers all in-flight states (sink busy, encode queue, encoding count). Exceptions in read/extract/encode/write/commit all funnel through `fail_()` → workers drain → `run()` rethrows. `tryCommit_` re-locks on all paths, and `std::map` node stability makes the unlock windows safe. `on_part`/`on_unit` (stats mutation) are serialized by `committing_`.
- **`ArrowPool` (area 6): `Reallocate` within a size class is safe** — I verified `classOf`/`classSize` satisfy `classSize(classOf(s)) ≥ s` for both old and new size, so in-place growth stays inside the mapping; `zero_size_area` and shrink paths are handled; `ReleaseUnused` only touches the shared free lists, so per-thread caches (≤2 MiB × threads, as documented) are unaffected; statistics batching error is within the documented threads × 1 MiB. `dying` correctly routes `~Local` through the shared path.
- **`TraceWriter` (area 7): the Parquet reserve hints are exact or upper bounds** (`rows`/`pts`/`id_bytes`/`seq_bytes` counted pre-`skip_empty`), except `ann.ReserveData(rows*8)` which assumes ≤ 8-char annotations — Arrow grows safely if exceeded, so at worst a slowdown, never wrong output. log8 quantization is correct for `decades > 0` (255 = vmax, 1 = vmax·10⁻ᵈ, 0 = zero; sub-floor values clamp to 1). `expand_rt` picks the right axis per row/level. `close()` is guarded by `closed_`, joins all shard threads, rethrows the first error after all files are closed, and the destructor swallows (no double-close). Row-group boundaries and `unit % shards` sink routing are fixed, so output is thread-count independent.
- **`DIATraceExtractor` (area 8): the empty-`cal` dereferences are all guarded.** `-rt_mode auto` + calibration throw → early return before `rt_map = std::move(cal->rt_map)`; `-mz_tol 0`/`-mz_tol_ms1 0` without a successful calibration → explicit `ILLEGAL_PARAMETERS`; `-ids` correctly restricts extraction only (panel is drawn from the whole library, and the option help says so); the stats JSON guards its `calibration` block. The one gap is finding 1. Also fine: `-ms1_isotopes -1` disables MS1 cleanly; negative `-unit_precursors` clamps to 1; `calibration:panel` absolute-size interplay with the pre-subsampled panel library is consistent (`copt.panel` absolute, so `panel_fraction` is not applied twice).
